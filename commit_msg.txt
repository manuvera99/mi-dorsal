fix: /test-geo con reset programático + detección de "denied" en filtro

Manu mandó capturas: Permissions API dice "denied" para mi-dorsal.vercel.app
aunque en chrome://settings el permiso se ve como "Permitir". Esto es el
comportamiento "sticky" típico: una vez denegado, el navegador no vuelve
a preguntar aunque permitas después en settings. Hay que "restablecer
permisos" explícitamente.

Cambios:

1. /test-geo reescrita. Cuando detecta state="denied" muestra un panel
   rojo con 4 opciones para arreglarlo:
   - Opción 1 (rápida): botón "Restablecer permiso de ubicación" que
     llama a navigator.permissions.revoke() (disponible en Chrome 116+).
     Un solo click y ya no necesitas ir a chrome://settings.
   - Opción 2: instrucciones paso a paso para chrome://settings con
     link directo a la página de configuración de este sitio
     (chrome://settings/content/siteDetails?site=https%3A%2F%2Fmi-dorsal.vercel.app)
   - Opción 3: desactivar extensiones (uBlock, Privacy Badger, AdBlock,
     Brave Shields, DuckDuckGo Privacy Essentials) que interceptan
     navigator.geolocation.
   - Opción 4: ventana incógnito (Ctrl+Shift+N) como test definitivo.
   - Instrucciones específicas por navegador (Chrome, Edge, Firefox, Safari)
     debajo del todo.

2. race-distance-filter.tsx: pre-check de Permissions API ANTES de llamar
   a getCurrentPosition. Si el estado es "denied", muestra mensaje claro
   "estado sticky, ve a /test-geo para resetear" y aborta. Evita la
   espera de 6s y la frustración de "no aparece el popup".

3. Añadido check de navigator.permissions.revoke() en /test-geo para
   saber si el navegador soporta la API programática.
