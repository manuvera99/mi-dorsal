fix: dos bugs críticos en geolocalización

## Bug 1: el endpoint IP pillaba la IP del servidor, no del cliente

Manu detectó que SIEMPRE le decía que estaba en Alemania, incluso
desde el móvil. El problema: `/api/geo/ip` llamaba a `ipwho.is/` SIN
pasar ninguna IP. `ipwho.is` veía la IP de quien le hacía la request,
que era el SERVIDOR de Vercel en Frankfurt. Por eso siempre Alemania.

Fix: extraemos la IP del cliente de los headers `x-forwarded-for`,
`x-real-ip` o `cf-connecting-ip` y la pasamos a ipwho.is en la URL.

```ts
// Antes:
const res = await fetch("https://ipwho.is/", { ... });

// Ahora:
const clientIp = getClientIp(req);  // lee headers
const res = await fetch(`https://ipwho.is/${clientIp}`, { ... });
```

También devuelvo la `clientIp` en la respuesta para debug.

## Bug 2: el selector de ciudades solo aparecía en una condición

El selector estaba condicionado a `coordsSource === "ip"`, así que si
el usuario tenía coords de sessionStorage de una sesión anterior (por
ejemplo manuales), no aparecía. Manu no veía el selector.

Fix: el selector de ciudades SIEMPRE visible. Es el método más fiable
porque no depende de IP ni GPS. Aparece en todos los casos.

## Bonus: mensaje GPS más neutro

Antes cuando `getCurrentPosition` fallaba con PERMISSION_DENIED, decíamos
"El navegador dice que el permiso está denegado". Esto presupone que
está denegado, pero hay otros casos (extensión bloqueando, iframe, etc.).
Ahora el mensaje es: "El navegador no devolvió tu ubicación".
